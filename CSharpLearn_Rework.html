C# & Unity guidebook

Useful mental models for tracing, learning, and debugging.

Four-pass code trace

1 · Name the state. Write each variable and the object or value it refers to.
2 · Walk each line. Update state after assignments, branches, calls, and every loop pass.
3 · Separate mutation from reassignment. Mutation changes an object; reassignment changes a variable’s reference.
4 · Predict, then run. Compare your trace with the Console or debugger.

Associative learning map

References ↔ code tracing: draw the object and its arrows before predicting output.
Unity lifecycle ↔ events: pair OnEnable subscriptions with OnDisable cleanup.
Collections ↔ OOP: use small components that own the data they manage.

Unity callback timeline

Awake — initialize this component’s own state.
OnEnable — connect behavior that follows the active state.
Start — one-time setup before first Update.
FixedUpdate — physics-step changes.
Update — frame input and frame behavior.

Debugging loop

Reproduce → state a hypothesis → inspect one value → change one thing → reproduce again. Keep the observation separate from the guess.
